摘要

航標貨櫃追蹤平台把裝在貨櫃上的 HB-T1 追蹤器回報的位置、門磁、溫度與震動，整理成可查詢、可與規格比對、可推送到客戶系統的事件紀錄。回報走行動網路與衛星雙模，涵蓋倉庫、港區、海上到目的地倉庫的整段運程；每一筆讀值都附時間戳與訊號來源。本文件列出平台與追蹤器的參數、整合介面、訂購型號與修訂紀錄，供評估與系統整合時查閱。

特性

  • 行動網路／衛星雙模回報；海上回報間隔 60 分鐘以內
  • 門磁、櫃內溫度、震動三種事件，10 秒內推送 Webhook
  • 讀值與規格集的上下限自動比對，超出即標記
  • REST API v2；速率上限依型號
  • 事件資料保存 24 到 60 個月
  • HB-T1 追蹤器 IP67，電池壽命 24 個月（15 分鐘回報）

適用

  • 海運整櫃貨主與貨運承攬
  • 冷藏櫃溫度紀錄（搭配 HB-T1R）
  • 港區、保稅倉與內陸貨櫃場的櫃況稽核
  • 拖車運輸的到站預估與交櫃確認
  • 不適用：散裝、空運與包裹件（§1.3）

§1.1 ［A4］用途

一只貨櫃從裝櫃到交櫃，平均經手六到八個單位：倉庫、拖車、港區閘門、船公司、目的港、目的地的拖車與倉庫。每一次交接，都是一段沒有人看著櫃子的時間。航標的工作是把這些時間填上資料：追蹤器每隔固定間隔回報一次位置與狀態，平台把它們接成一條完整的時間線，再與合約上寫的規格比對。

平台不取代船公司的艙單，也不取代港區的 EDI；它補的是那幾段沒有人回報的空窗——海上、堆場、拖車上。讀值怎麼回報、間隔多久、誤差多大，都寫在 §2.1 ［A6］；怎麼接進既有系統，見 §3 ［A8］。

§1.2 ［C4］系統組成

HB-T1 追蹤器裝在貨櫃門樑內側，不鑽孔GNSS ・ 門磁 ・ 三軸加速度 ・ 溫度探頭（HB-T1R）
回報通道　4G LTE-M（陸上、港區）／L-band 衛星（海上）
航標平台事件時間線、規格比對、保存每筆讀值附時間戳與訊號來源
輸出　REST API v2／Webhook／儀表板／CSV
客戶系統ERP、TMS、報表或自建看板

§3.1 ［A8］認證與速率

所有請求經 HTTPS 送到 api.hangbiao.example，以 API 金鑰認證；金鑰在儀表板建立，可限制來源 IP 與到期日。回應一律為 JSON，時間以 ISO 8601 的 UTC 表示，時區由客戶端換算。

GET /v2/containers?link=sat&limit=50 HTTP/1.1
Host: api.hangbiao.example
Authorization: Bearer hb_live_7f3c9a2e...
Accept: application/json
速率上限
依型號（§4.1 ［A11］）；超過時回 429 並附 Retry-After。
剩餘額度
每個回應帶 X-RateLimit-Remaining 標頭。
分頁
cursor 參數；每頁最多 500 筆。
重送
Webhook 收到非 2xx 時依 tRETRY 重送，最多 12 次；推送紀錄可在 /v2/webhooks/{id}/deliveries 查。
